# 修改流程
修改既有技能/代码的独立路径（不接在收尾之后）。
## 动作
1. 定位改动面：文件清单 + 受影响知识叶 + 受影响脚本 + 受影响约束。
2. 影响分析：是否触及红线（≤50 行、悬空链接、只引用不内嵌）；触及即先改约束再改码。
3. 增量取证：新出现的未知 API/报错 → 走浏览器学习，禁凭记忆补写。
4. 回归：重跑构建测试 + 整体审查（check_links / lint_check 双归零）。
5. 版本：CHANGELOG 记 0.x.y 与变更条目；git 走 `feature/fix-<topic>` → `dev`。
## 产出
- 标记「完成项目修改」并收口返回调度方整合续排。
## 兜底
- 改动与既有约束冲突且不可两全：记中断交用户裁决，不得静默放宽红线。
